### Fixed

- **The extension-template copy end-to-end test pins every child `dotnet` it starts to folders of its
  own.** The test packs the four SDK packages, restores a copy of the template against that feed and
  builds it with `--no-restore`. Those children shared the runner's CLI home, NuGet HTTP cache, temp
  directory and MSBuild server with every other assembly of the same verify shard, and a restore or
  build that runs beside another through a shared temp directory and HTTP cache is the shape this
  repository already isolates for the gate's fixture restores — on Windows, where a file another
  process holds cannot be replaced, that collision is what fails the child. Each child now gets a
  private `DOTNET_CLI_HOME`, `NUGET_HTTP_CACHE_PATH` and `TMPDIR`/`TMP`/`TEMP` under the test's own
  temp directory, no MSBuild server or node reuse and a single node, as the fixture restores do, and
  a wiring test pins the isolation beside the packages folder the same test owns (#938).
