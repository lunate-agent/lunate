### Fixed

- **The verify gate proves the contract from the feed it just packed, whatever the source order
  is.** `verify-powershell (windows)` and `verify (windows-latest, 1/4)`/`(2/4)` went red on the push
  of 49e4b54e — the three legs whose gate restores the template against the freshly packed feed —
  while every other leg passed. The roundtrip restores into a packages folder of its own since
  #932, but a release also serves the same contract on nuget.org under the same id and version, so
  which source answers is NuGet's source order rather than the gate's intent. The roundtrip now
  carries a `nuget.config` of its own: `<clear />`ed sources, the packed feed, nuget.org for the
  test SDK, and a `packageSourceMapping` that lets a `Lunate.*` package come from the packed feed
  and from nowhere else. `--configfile` also keeps a runner's machine-wide NuGet configuration out
  of the run. The same configuration serves `scripts/verify.sh`, its `verify.ps1` twin and
  `ExtensionTemplateCopyEndToEndTests`; tests pin both the wiring and the mapping's behaviour when
  the released feed is named first (#936).
- **The configurations the gate writes escape the path they name.** The feed path is written into an
  XML attribute, and a temp directory may hold `&` (Windows allows it in a profile path) or `<`
  (valid on Unix): written raw, `nuget.config` is malformed XML and the restore fails before it can
  prove anything, which would redden the same Windows legs for a reason that has nothing to do with
  the contract. `scripts/verify.sh` (`xml_attribute`), its `verify.ps1` twin
  (`ConvertTo-XmlAttribute`) and `ExtensionTemplateCopyEndToEndTests` (`XmlAttribute`) now encode the
  five characters an attribute cannot carry raw, for the contract roundtrip's configuration and for
  the extension package roundtrip's; a test runs the bash helper and parses the result back as XML,
  and pins that no configuration site interpolates a raw path (#936).
