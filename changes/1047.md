### Added

- **`generate_image`, the image-generation tool.** A prompt in, an image out: the tool asks the
  profile named by `usages.image` for one image with the optional workspace `path` argument, keeps
  the bytes content-addressed in the session's own sidecar directory and attaches them to the
  conversation as the typed image part, so the transcript shows `[image <w>x<h>]` and never base64.
  With a path the same bytes are written into the workspace under the write tool's path rules and
  approval. The tool is offered only when the usage resolves, so an unset `usages.image` changes
  nothing (#1027).
- **The `image` usage.** `usages.image` gains the role ADR-0027 named but left unbuilt: its declared
  requirement is the model's image output, it is served on the `openai-chat` family only, and its
  calls are charged and recorded as usage `image` with their profile, provider and model, so `/cost`
  groups them under their own usage. No session schema change: schema 4's attribution usage is a
  free string (#1027).
