### Changed

- **The documentation check is written down as a contract, not just wired into CI.** A new
  `documentation` capability states that every relative link and `#anchor` resolves, that every
  redirect is the four-line stub, that `docs/docs.json` lists each user-path page exactly once and
  that every user-path page carries a runnable marker or a `proseOnly` reason, while `ci-pipeline`
  names `scripts/docs-check --check` in the OS-independent set, in the docs profile and in the
  documentation-only push, so deleting the step is a spec change instead of a quiet regression
  (#818).
