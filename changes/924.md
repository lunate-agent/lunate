### Fixed

- **A CI leg GitHub never gave a runner is retried instead of filed as a code failure.** The push run
  `43904858046` went red on `main` with nothing failing: `verify (macos-latest, 1/2)` and
  `perf (macos-latest)` were cancelled before their first step — GitHub's own annotation was "The job
  was not acquired by Runner of type hosted even after multiple attempts", beside its macOS arm64
  capacity notice — while every job that did get a runner was green. Such a run is now a
  runner-capacity red: the reporter writes the abandoned legs into the run summary and defers,
  `.github/workflows/ci-capacity-retry.yml` reruns that run's failed jobs once when it completes, and
  only the attempt the retry budget does not cover files the card (`CI failed: <job>`, with the capacity
  cause in its body). A job that ran is never retried this way, so no executed failure is retried away
  (#923).
