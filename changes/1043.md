### Changed

- **The verify shards place whole test projects by recorded weight, and the process suite is its own
  project.** The Windows lane recorded 561 s, 900 s, 162 s and 467 s, with shard 2/4 at 43 % of the
  lane because it owned `Lunate.Coding.Tests` and five small projects. The shard scheduler now places
  one whole test project, both culture passes together, largest recorded weight first into the
  least-loaded shard, so every `lunate.slnx` test project is in exactly one shard. The process-bound
  Bash and Process tests moved into `Lunate.Coding.Process.Tests`, linked from their old source
  folders, so one shard no longer carries the whole slow Coding suite. On the recorded table the
  Ubuntu and Windows four-shard loads are 704 s, 960 s, 704 s and 704 s of 3072 s, a pole of 31.25 %
  (inside the third). The before/after is measured: the position partition's own `main` run
  (`46105412860`, commit 218aa75d) took 748 s, 887 s, 134 s and 480 s on the Windows verify step (a
  887 s pole; the issue's earlier record was 900 s), and the split's measurement run
  (`measure-timing-win-x64-*`, run 46114774702, commit 7fb6c096) took 715 s, 759 s, 517 s and 331 s, so
  the pole fell to 759 s (14.4 % below the same run's 887 s and 15.7 % below 900 s). The final table's
  `#primary` row moves the 480 s `Lunate.Extensibility.Testing.Tests` out of the 715 s shard into a
  shard of its own, while `Lunate.Coding.Tests` remains the measured 759 s shard, so the final
  `#primary`-aware assignment's pole is 759 s. macOS keeps its two-shard cap and is measured as well:
  on the same machine the position partition's test phase took 172 s and 3627 s (its de-AT shard
  includes the sandbox's process-tree timeout, recorded as skew) and the weight partition 954 s and
  966 s, so its busiest shard fell from 3627 s to 966 s; the position partition's own CI run measured
  398 s and 913 s. The gate reports the recorded-weight comparison of 1536 s against 2216 s and the
  predicted wall pole of 960 s against 1070 s. The weights live in
  `scripts/verify-shard-weights.tsv`, including the `#primary` row for shard 1's non-test steps, and
  are refreshed from a run's own records through `scripts/shard-weights.sh` rather than estimated.
- **Every gate test path now leaves those records.** A pass that fails after its retry budget and each
  pass of the opt-in pooled runner used to exit without calling the per-project recorder; both now
  write their records before the leg exits, and `tests/scripts/test_verify_project_recording.py` pins
  those paths. `scripts/gate-tests.sh` keeps checking completeness, non-overlap, determinism, the
  `#primary` row, the longest-processing-time bound and the third at the Ubuntu and Windows shard
  count (#1043).
