### Fixed

- **A session file that two appends reach at once is no longer corrupted.** A tool that records a
  usage during its call — `generate_image` charges its run as usage `image` — appends that record
  while the run appends the message the call produced. Both appends read the file's end at the same
  moment, so the second line landed on top of the first one's head and the session no longer loaded:
  that is what failed `verify (macos-latest, 2/2)` in run 46122054216. The append is one critical
  section now (entry id, parent, line and in-memory entry), so a session has one writer inside the
  process as well as across processes (#1051).
