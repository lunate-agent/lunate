### Changed

- **The SWE-bench sample is 50 Verified instances and the run names three arms as data.** The pinned
  subset is every 10th id in lexicographic order of the 500-instance Verified test split (indices 0,
  10, …, 490), recorded in `eval/swebench/instances.txt` with its rule, and `eval/swebench/run.json`
  names the three arms the numbers will come from: the budget model with `semantic_search` off, the
  same model with it on, and the mini-swe-agent budget baseline (no frontier arm). Each arm entry
  names its `tool`, `tier`, model id and credential variable, and a Lunate arm names
  `semanticSearch`; the on arm also names its embeddings model and that model's credential, from
  which the orchestrator generates a `LUNATE_HOME` whose `tools.extra` enables the tool and whose
  `usages.embeddings` binds the profile, while the off arm runs with no home at all. The definition
  loader refuses an unknown tool, a duplicate arm, an on arm without an embeddings model, and a
  baseline whose model no Lunate arm runs. One run costs no more than the US$4.00 cap. The summary
  records each arm's own name and the `semantic_search` call count per instance and per arm —
  counted from `tool_call_start` events, never as a step — and an arm that mixes a chat model with
  an embeddings model is priced from the per-record prices its trajectory carries. The committed
  five-instance summary stays the record of the run that produced it, with that run's definition
  beside its evidence (#1052).
