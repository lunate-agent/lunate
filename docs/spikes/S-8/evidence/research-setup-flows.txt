OpenCode
--------
CLI facts (2026-11-08):
- `opencode auth --help` describes "manage integrations and credentials" and
  lists list/login/logout/export/import/switch.
- `opencode auth login --help` takes an optional integration target, `--method`
  and repeatable `--answer key=value`.
- `opencode auth list` prints integration, method and state, e.g.
  "OpenCode Go  API key  stored", "GitHub Copilot  OAuth  stored".
- Every command accepts a global `--wizard` flag.

Shipped documentation read on 2026-11-08:
- https://opencode.ai/docs/cli/providers/
  - "/connect lists the integrations available from the current server and
    project. Select a provider, choose an authentication method when it offers
    more than one, and follow the prompts."
  - "Run /connect again to add another account. Selecting an already connected
    provider opens its account list, where you can activate, rename, or delete
    a saved account."
  - "The CLI and TUI render those forms before starting authentication."
  - "Each successful API-key, OAuth, or command login creates a saved account.
    The newest account becomes active."
  - "Saved API keys and OAuth tokens live in the server's SQLite database."
- https://opencode.ai/docs/providers/
  - "/connect, choose a provider, and enter its credentials. Then run /models to
    select one of its models."
  - Custom providers are declared in opencode.jsonc, not collected by /connect.

Pi
--
From the installed package docs (pi 1.3.0):
- docs/providers.md: "Most hosted providers support one or both of these
  authentication methods: Sign in through a browser or device flow backed by
  OAuth; Provide an API key." "/login [provider] to see the methods supported
  by a provider."
- docs/providers.md: auth.json can hold API keys and OAuth tokens; a key may be
  a literal, an environment variable name, or a command prefixed with `!`.
- docs/quickstart.md: "In Pi, run /login. Choose a provider, then follow the
  prompts to use a subscription or store an API key."
- docs/slash-commands.md: `/login [provider]` "Add provider authentication";
  `/logout` "Remove provider authentication".
- Pi has no separate first-run wizard: it opens the session and `/login` is a
  slash command. Custom providers are configured in models.json.
- `pi auth` is only print/check, not the login entry point.

Gemini CLI
----------
Installed bundle: /opt/homebrew/lib/node_modules/@google/gemini-cli/bundle/
interactiveCli-WWICCK5B.js (gemini 0.41.2). The AuthDialog component:
- Heading: "Get started".
- Question: "How would you like to authenticate for this project?".
- Rows: "Sign in with Google", "Use Gemini API Key", "Vertex AI"; Cloud Shell
  or metadata-server rows appear only when the environment says so.
- `settings.merged.security.auth.enforcedType` filters the rows to one method.
- The initial row comes from `security.auth.selectedType`, then
  `GEMINI_DEFAULT_AUTH_TYPE`, then an existing `GEMINI_API_KEY`, then
  "Sign in with Google".
- The API-key dialog says "Please enter your Gemini API key. It will be
  securely stored in your system keychain." and links "You can get an API key
  from ...".
- Auth errors render inline in the same dialog.
- The dialog ends with the Terms of Services and Privacy Notice link.
